## 1. QuantRail 是什麼

QuantRail 是一個 Python 函式庫，用於**值得信任的量化研究**。它提供三項多數回測框架留給使用者自行處理的能力：

1. **資料治理。** 每個資料集都是有版本、有雜湊值的快照，並附有 manifest，記錄資料從何而來、適用哪些條款、包含哪一種價格，以及每個數值在何時可被得知。
2. **與帳本一致的模擬。** 財富由帳本根據原始價格與明確的事件（成交、手續費、稅、股利、分割、資金費率、交割）計算，而不是把部位乘上報酬率。每一天淨資產價值的變動都必須解釋到分。
3. **研究紀律。** 試驗在執行前登記，且永不刪除；實驗契約在看到結果之前凍結；樣本外資料（holdout）會被封存；統計方法（配對區塊 bootstrap（paired block bootstrap）、多重比較校正（multiple-comparison correction）、Deflated Sharpe Ratio（DSR）、回測過度擬合機率（PBO））均已內建。

目標是：以 QuantRail 產出的結果，本身就能表明它可以被信任到什麼程度。

### 非目標

- QuantRail **不附帶任何市場資料**，也不提供針對條款禁止自動存取之來源的爬蟲。
- 它不是券商連接器，也不是實盤交易引擎。日後可以在其契約之上建立執行服務；憑證永遠不屬於本 repository。
- 它不保證策略能獲利。「沒有任何規則勝過基準」是一個有效且完整的研究結果。

## 2. 原則

| 原則 | 結果 |
| --- | --- |
| 單一的帳務真實來源 | 回測與任何未來的執行共用同一套帳本與成本契約。市場之間以模組區分，而不是分叉出各自的引擎。 |
| 財富使用原始價格，調整後序列只用於訊號 | 股利與分割是帳本中的事件。總報酬指數可以驅動訊號，但絕不用來評價部位。 |
| 時間點正確（point in time） | 每筆紀錄都帶有它變得可取得的時間。訊號只能讀取決策時點已可取得的資料；測試會檢查截斷未來資料後，過去的訊號保持不變。 |
| 「未知」是一個值，不是錯誤 | 來源資訊、授權、價格口徑與可得時間都可以是 `unknown`。它們會被記錄下來，並在信任報告中以警告呈現；不會阻擋私人研究（[ADR 0002](../adr/0002-unknown-provenance-is-a-value.md)）。 |
| 只使用明確版本 | 資料集與契約依明確的版本載入，並以雜湊驗證。沒有 `latest`。 |
| 與市場無關的核心 | 數量是 `Decimal`，其最小變動單位由商品定義；現金按幣別分開持有。核心中沒有任何部分假設特定的交易所（[ADR 0003](../adr/0003-market-agnostic-core.md)）。 |
| 預設拒絕（fail closed），並說明原因 | 當證據不足以支持某個動作（沒有有效報價、買不起的委託、未知的規則）時，結果是附帶原因代碼的拒絕，絕不憑空編造數值。 |

## 3. 分層

```text
quantrail
├── core          商品、數量、幣別、來源資訊、信任旗標
├── data          原始批次、manifest、整理後資料集、使用者資料匯入
├── accounting    多幣別帳本、部位、交割、公司事件
├── markets       市場模組：tw_equity（首個）、crypto（下一個）
├── engine        每日模擬迴圈：決策 -> 委託 -> 成交 -> 帳本
├── research      試驗登記、凍結契約、樣本外資料封存
├── stats         指標、配對區塊 bootstrap、Holm、DSR、PBO
└── report        信任報告與結果摘要
```

依賴關係只會向下：`core` 不依賴 QuantRail 中的任何東西；`markets` 依賴 `core` 與 `accounting`；`engine` 依賴其上方的所有層；`research` 與 `stats` 不依賴任何特定市場。

## 4. 核心概念

| 概念 | 意義 |
| --- | --- |
| `Instrument` | 穩定的識別碼、交易場所、資產類別、報價幣別、數量的變動單位與最小值、價格跳動單位。 |
| `Quantity` | `Decimal`，依商品的變動單位驗證（1 股、1000 股、0.00001 BTC）。 |
| `Money` | `Decimal` 金額加上幣別。跨幣別的運算需要明確的換算。 |
| `Provenance` | 來源、授權、條款網址、取得時間；每個欄位都可以是 `unknown`。 |
| `Declaration` | 資料集對自身的聲明：價格口徑（原始／分割調整／總報酬／未知）、可得時間規則、是否包含公司行動。 |
| `TrustFlag` | 機器可讀的注意事項（`LICENCE_UNKNOWN`、`ACCOUNTING_APPROXIMATE`、`AVAILABILITY_UNVERIFIED`……），附有嚴重程度與訊息。 |
| `LedgerEvent` | 成交、手續費、稅、現金股利的權利確立與發放、分割、資金費率支付、交割。 |
| `MarketModule` | 提供一個市場的交易日曆規則、成本模型、交割規則、委託限制與事件類型。 |

## 5. 資料治理

```text
抓取（adapter，使用者自己的憑證）        ─┐
                                          ├─> 原始批次：收到的原始位元組 + manifest（URL、時間、SHA-256、來源資訊）
使用者檔案（CSV / Parquet / DataFrame）  ─┘
        │
        ▼
整理（確定性、離線）──> 整理後資料集版本：資料表 + manifest（來源、聲明、檢查、信任旗標）
        │
        ▼
依 (dataset_id, version) 載入 ──> 經雜湊驗證的資料表 + manifest + 信任報告
```

- 原始批次只能附加，永不覆寫。不完整的批次無法進行整理。
- 整理是離線且確定性的：相同的原始批次與程式碼會產生相同的資料表。
- `ingest()` 是使用者從其他地方取得之資料的進入點。只有價格表是必要的；其餘一切預設為 `unknown` 並會被回報。
- Adapter 位於 `quantrail.data.sources`。只有在來源的條款允許程式化存取時，才會接受該來源的 adapter；每個 adapter 都記載這些條款，並自動填入來源資訊。受限制的供應商可以作為選用的 extras，並如實記載。

### 何時必須知道來源資訊

私人研究永遠不需要。匯出或分享資料集、發表報告，以及任何商業用途則需要：當授權為 `unknown` 時，這些操作會拒絕執行，或要求明確的確認。

## 6. 帳務與模擬

引擎每個交易時段執行一次迴圈：

1. 套用在開盤前生效的事件（分割、股利權利確立、資金費率）。
2. 將待處理的目標轉為委託；依市場的限制與實際可用的現金決定委託數量（應收款項不可動用）。
3. 以模型價格成交；入帳手續費與稅；排定交割。
4. 完成到期的交割；將已發放的股利轉為現金。
5. 以收盤評價（無法交易的日子使用最後一個有效價格，並加上旗標），並檢查以下恆等式

   `Δ NAV = overnight P&L + intraday P&L + entitlements − fees − taxes − slippage`。

無法交易的交易時段會產生 `NO_FILL` 並附上原因（`SUSPENDED`、`RAW_PRICE_MISSING`、`INVALID_QUOTE`、`INSUFFICIENT_CASH`、`LOT_CONSTRAINT`）。屬於研究選擇的政策（訊號時點、不交易區間、股利再投資、期末清算）是研究的參數，而不是市場模組的參數。

### 第一個市場模組的驗收測試

台股模組必須逐日重現一個參考用的買進持有模擬：標的為一檔 ETF，期間八年，含十六次配息與一次 1 拆 4 的分割；該模擬為獨立建置，並已與總報酬指數核對。此參考僅以私人形式存在，用於驗證移植結果；資料本身不會散布。

## 7. 研究紀律

- **試驗登記。** 只能附加的 JSONL。試驗在執行前為 `REGISTERED`，並且恰好取得一個終止狀態（`COMPLETED`、`FAILED`、`BLOCKED`）。每筆紀錄包含設定雜湊、資料 manifest 雜湊、程式碼 commit、dirty 旗標與原始碼指紋。
- **凍結契約。** 一項研究的規則與評估準則記錄在契約檔中。執行時會拒絕尚未凍結的契約。事後的釐清以決議（resolution）記錄，並附上決策當時的已知狀態。
- **樣本外資料封存。** 開發期之後的資料會在策略看到之前移除；解除封存是一個明確且留有紀錄的選項。
- **統計。** 共用索引的配對循環區塊 bootstrap（paired circular block bootstrap）、跨挑戰者的 Holm 校正（Holm correction）、Deflated Sharpe Ratio、CSCV 回測過度擬合機率，以及 BRAIN 風格的摘要指標。以上皆不呈現為未來獲利的機率。

## 8. 公開與私有的界線

| 公開（本 repository） | 私有（你的環境） |
| --- | --- |
| 函式庫程式碼、市場模組、寬鬆授權來源的 adapter | 憑證、排程、部署 |
| 合成的測試 fixture | 市場資料（原始與整理後） |
| 使用開放授權資料的文件與範例 | 你不想公開的策略、研究與結果 |
